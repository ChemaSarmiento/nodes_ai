# Purpose

This section defines AML cases based on deviations from expected customer behavior.

Unlike previous cases that analyze money movement only, these compare observed activity against the customer's declared profile.

---

# Case 4

## AML_NEW_EXTERNAL_ACCOUNT

### Objective

Detect withdrawals toward previously unseen destination accounts.

---

## Business Question

```
Is the customer sending money to an account that has never been used before?
```

---

## Graph

```
Client

↓

Contract

↓

Withdrawal

↓

ExternalBankAccount (new)
```

---

## Detection Rule

```
Movement Type = Withdrawal

AND

External Account has never appeared
for the same client before.
```

---

## Optional Future Enhancements

Increase severity if:

```
New Country

High Risk Country

New Device

Impossible Travel

High Amount
```

---

## Features

```
account_age_days

withdrawal_amount

days_since_last_withdrawal

is_first_destination

institution_hash
```

---

## Severity

LOW

```
Small withdrawal
```

MEDIUM

```
New destination

+

Medium amount
```

HIGH

```
Large withdrawal

+

First destination
```

---

## Evidence

```
Withdrawal

Destination Account

Timeline

Contract
```

# Case 5

## AML_KYC_INFLOW_MISMATCH

### Objective

Detect deposits inconsistent with declared customer profile.

---

## Business Question

```
Does observed inflow exceed declared financial profile?
```

---

## Required Inputs

```
KYC

↓

Expected Monthly Inflow Bucket
```

```
Deposits

↓

Current Month
```

---

## Detection Rule

```
Monthly Deposits

>

Expected Maximum Bucket
```

---

## Bucket Mapping

Example

```
0 - 50K

↓

Maximum = 50,000
```

```
50K - 250K

↓

Maximum = 250,000
```

Future

Move buckets to configuration table.

---

## Features

```
expected_bucket

observed_amount

ratio

industry

activity

deposit_count
```

---

## Severity

LOW

```
Observed <= 1.2 x Expected
```

MEDIUM

```
Observed <= 2 x Expected
```

HIGH

```
Observed > 3 x Expected
```

---

## Graph

```
Client

↓

KYC Profile

↓

Expected Bucket

↓

Deposits
```

---

## Explanation

The packet should clearly state

```
Expected

Observed

Difference

Ratio
```

# Case 6

## AML_TOP_CONTRACT_FLOW

### Objective

Aggregate money movement across contracts belonging to the same customer relationship.

---

## Motivation

Many customers have multiple contracts.

Example

```
Trading

↓

Smart Cash

↓

Future Products
```

Individually

Nothing unusual.

Combined

Potential AML concern.

---

## Detection Rule

```
Same Top Contract

AND

More than one Contract

AND

Aggregate Cash Flow

>

Configured Threshold
```

---

## Features

```
contract_count

top_contract

deposit_total

withdrawal_total

cash_velocity

contract_types
```

---

## Graph

```
Client

↓

Contract A

↓

ContractGroup

↑

Contract B

↓

Movements
```

---

## Severity

Depends on

```
Amount

Contracts

Velocity

Future

Behavior
```

# Design Rules

Rule 1

Cases never modify business entities.

---

Rule 2

Cases reference graph entities.

---

Rule 3

Evidence must be reproducible.

---

Rule 4

Severity is deterministic.

---

Rule 5

Explanation is generated after the graph is built.

---

# ADR

ADR-011

Profile-based AML Detection

Decision

Business profile comparisons are first-class AML signals.

Reason

Many suspicious behaviors are deviations from expected activity rather than absolute thresholds.
